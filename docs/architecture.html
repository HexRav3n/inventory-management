Architecture overview

Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talks to a FastAPI service over HTTP. The service serves read-only mock data that it loads from JSON files into memory at startup. There is no database, no authentication and nothing persists.

Data flow: changing a filter

Most of the app follows this path. Example: a user picks Tokyo and March 2025 on the Orders page.

  1. The user changes a filter in the FilterBar
    The v-model writes to refs declared at module scope in useFilters. Every view shares one copy of the filter state (singleton pattern), so filters survive navigation.
    components/FilterBar.vue · composables/useFilters.js
  2. The active view's watcher fires
    Dashboard and Orders watch all four filters. Inventory, Demand and Backlog watch only location and category, because inventory has no time dimension. Spending watches only the period.
    views/*.vue → watch([...])
  3. The view calls the API client
    getCurrentFilters() returns { warehouse, category, status, month }. api.js builds a URLSearchParams string and leaves out any value equal to 'all'.
    client/src/api.js
  4. An HTTP GET goes to FastAPI
    GET http://localhost:8001/api/orders?warehouse=Tokyo&month=2025-03. This is a cross-origin request; CORS allows all origins.
    server/main.py
  5. The handler filters the in-memory lists
    apply_filters matches warehouse exactly and category and status case-insensitively. filter_by_month then does a substring match on order_date, and expands quarters such as Q1-2025 through QUARTER_MAP. The original lists are never modified.
    apply_filters() · filter_by_month()
  6. The handler aggregates and serializes
    List endpoints are validated against a Pydantic response_model. /dashboard/summary computes KPIs on the server: inventory value, low-stock count, pending orders and total order value.
    Pydantic models · get_dashboard_summary()
  7. The view renders reactively
    Raw arrays go into refs such as allOrders and inventoryItems. Computed properties derive tables, KPIs and SVG charts. useI18n translates labels, and formatCurrency converts USD to JPY at a fixed rate of 150.
    computed() · composables/useI18n.js · utils/currency.js

Observations

Things worth knowing before you change the code.

  • Gap
    The task API doesn't exist.
    App.vue calls /api/tasks, gets a 404 and logs it to the console. Tasks still appear because hard-coded mock tasks from useAuth are merged in, but tasks you add don't persist.
  • Gap
    Purchase orders are only half built.
    /api/backlog reads purchase_orders.json, which is empty, to set has_purchase_order. The client's create and get calls have no matching routes.
  • Drift
    Backlog.vue is orphaned.
    It is a complete view, but it isn't registered in main.js and has no nav link. The Dashboard shows backlog data through BacklogDetailModal instead.
  • Drift
    Reports.vue breaks the conventions.
    It uses the Options API (this.loading), hard-codes the API URL, bypasses api.js, leaves console.log calls in place and has a non-translated nav label.
  • Drift
    generate_data.py is stale.
    Its product catalog (Widgets, Components, Equipment…) doesn't match the current categories (Circuit Boards, Sensors…). Re-running it overwrites orders.json with categories that the FilterBar can't select.
  • Limit
    Dates are hard-wired to 2025.
    QUARTER_MAP, the FilterBar month options and the quarterly report all assume 2025. Month filtering is a substring match on the ISO date string.
  • Limit
    The backlog KPI ignores filters.
    total_backlog_items in /dashboard/summary always counts all backlog items, whatever filters are active.
  • Note
    The API base URL is hard-coded.
    http://localhost:8001/api appears in api.js and Reports.vue. Deploying anywhere else needs an env variable or a Vite proxy.
  • Note
    Demo-grade security.
    There is no auth, CORS allows * with credentials and there is no rate limiting. The data is read-only and resets on every restart.
